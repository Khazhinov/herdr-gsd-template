## 3. Multi-vendor and owner switch

### 3.1 Adding Kimi CLI or OpenCode with GLM

Launch is data-only: an `[agents.<id>]` entry with `command`, `prompt`, `capabilities`, `cost_tier`, `stability` is enough, `route.py` has no agent ids. The quota side is not:

1. Probe kinds are a closed set (`config.py:11`, `quota.py:219-235`). Without an API, the choices are `none` (heavy work fails closed, light work goes in blind) or `static` (manual percent, see C18). A generic `quota = "cmd"` probe (an external command printing the normalized JSON) would let a vendor without an official API plug in a parser of its own logs without changes to `orchlib`.
2. Account identity is derived from the probe kind (`quota.py:213-216`): only `codex` and `claude` variants share an account. Two OpenCode GLM models on one z.ai key, or two Claude logins (`CLAUDE_CONFIG_DIR`), cannot be expressed. An explicit `account` field in `agents.toml` is required; costs, pending, `max_parallel` (C14) and the cache (C5) must key on it.
3. Without a quota reading the scheduler has no feedback: a worker that dies on a vendor limit is collected as `incomplete` and the same agent is chosen again. A cooldown (agent unavailable until a given time after a limit failure, recorded at `collect`) closes this gap.
4. Worker facts to verify per CLI before `stability = "supported"`: OSC 7501 status (otherwise every dispatch reports a failed `startup_check`), semantics of `hc.wait(name, timeout=120)` before `hc.send` for `prompt = "send"` (requires clarification: what event it waits for), the sandbox and approval mode, and report writing. `installed()` checks `command[0]`; a command wrapped in `env` or `sh` would always count as installed.

### 3.2 Switching the owner when its vendor quota runs low

Current state: `owner` is a committed field of `routing.toml`; OPERATIONS section 5 requires a safe boundary (nothing `running`), a GSD install for the new runtime and a separate commit. Nothing triggers the procedure. Required:

1. Owner budget (C7): a reserve for the owner's account and a warning in `status`/hub when it approaches it, so that the owner reaches a durable boundary while it still can.
2. `owner` capability: only `claude` has it in `agents.toml`; `validate` rejects `owner = "codex"` until the capability is added and the owner role is tested in the target environment.
3. Allow the owner in `routing.local.toml` (git-ignored) for a temporary switch, so that a quota-driven handoff needs no commit to canonical files; record the switch in `runtime/decisions.jsonl`.
4. Quota visibility after the switch: the Claude reading comes only from statusline renders. With a Codex owner and no Claude session it goes stale after 30 min, and heavy Claude work fails closed until a light Claude task refreshes it. Document this or let the hub keep the last reading with its age (C11).
5. Bootstrap and reconcile are Claude-specific (as Codex notes); the new owner also needs its runtime-specific bootstrap file, and `AGENTS.md` must distinguish the owner from a worker of the same runtime by the dispatch contract, not by `routing.toml` alone, because a Codex worker reads that Codex is the owner.
6. Review independence (C4) must then exclude the new owner's account and the author of the change.

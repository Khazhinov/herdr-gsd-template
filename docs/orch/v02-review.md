## Routing: what is missing for multi-vendor (Kimi, GLM via OpenCode) and owner switch

- The registry can launch a new CLI from TOML, but live quota support is hard-coded to `codex` and `claude` (`config.py:11`, `quota.py:213-235`). Kimi and OpenCode/GLM therefore need a manually maintained `static` budget for heavy routing; `none` fails closed. Adding provider telemetry requires code changes or a generic probe interface. Define an explicit `quota_account` separately from `quota` so multiple OpenCode models or Kimi variants can share one account ledger; today only Codex and Claude variants share a key.
- Kimi and ZCode are intentionally excluded by `auto_stability = ["supported"]` and their `candidate`/`experimental` values. There is no OpenCode/GLM entry, quota probe, or smoke-test artifact in this range. Promote only after verifying prompt delivery, status, sandbox, and report behavior for each CLI.
- A review routed back to the owner is explicitly marked `independent: false` (`route.py:81-104`), but still produces a completed review task. If an independent review is a required gate, the owner workflow must reject that outcome or route to another eligible provider. Manual override can also choose the owner even while a non-owner is eligible.
- Changing `routing.owner` changes validation and review preference, but bootstrap still requires and installs Claude (`bootstrap.sh:18-39`), while reconcile writes Claude-specific owner instructions and statusline settings (`reconcile-runtime-config.py:20-37`). The documented handoff requires a manual GSD install and configuration review. Make bootstrap/doctor follow the selected owner and verify that the new runtime has GSD, owner instructions, and a committed safe boundary before accepting the marker change.

# Архитектурные решения v0.2

| # | Решение | Обоснование | Альтернатива и причина отказа |
|---|---|---|---|
| D1 | Python 3.11 stdlib, конфигурация в TOML | `tomllib` в stdlib, существующие скрипты на Python, ноль зависимостей | YAML требует PyYAML; JSON без комментариев |
| D2 | Один CLI `scripts/orch.py` и пакет `orchlib` | одна точка входа для агента-владельца; тестируемые модули | набор shell-скриптов v0.1 плохо тестировался |
| D3 | Квота Codex из `codex app-server` (`account/rateLimits/read`) | живые данные за 1 с без активной сессии Codex; журналы остаются запасным путём | только журналы сессий: устаревают между сессиями |
| D4 | Квота Claude из входа statusline (`rate_limits`) через tap | официальный источник, обновляется при каждом ответе владельца; пользовательская строка сохраняется цепочкой | недокументированный OAuth-эндпоинт usage отклонён |
| D5 | Устаревшая квота (> 30 мин) считается неизвестной | честность важнее доступности; тяжёлая работа уходит дальше по цепочке | использовать последнее значение: завышает остаток |
| D6 | Одноразовый воркер на задачу (`hc run`), без `/clear` и перезапусков | свежий контекст по умолчанию, cwd задаётся при запуске | постоянные peer-панели v0.1 |
| D7 | Воркер не коммитит, коммит в `collect` | песочница Codex защищает `.git` | `danger-full-access` противоречит безопасным значениям по умолчанию |
| D8 | Завершение через `hc wait --children` и отчёт, без обязательного `hc send` | `hc send` из песочницы требует подтверждения | обязательное оповещение блокировало бы воркера |
| D9 | Worktree внутри репозитория | наследование доверия папки, без диалога у безлюдного воркера | `~/.herdr/worktrees` (соглашение App) требует доверия на каждый worktree |
| D10 | Дашборд как мод Herdr App, реактивный через метки терминала hub | без опроса, данные ядра живые, мод не хранит бизнес-состояние | опрос `exec` по таймеру: лишние перерисовки и задержка |
| D11 | Встроенные `plan_check` и `code_review` GSD выключены в профиле lean | ревью выполняет независимый воркер с учётом квот | встроенные линии `/gsd-review` вызывают CLI разово, без квот: оставлены для профиля strict |
| D12 | Мост `cross_ai_command` реализован, но выключен | GSD исполняет делегированный план в корне без worktree; владелец теряет контроль ревью до слияния | включение по умолчанию |
| D13 | Kimi и ZCode в реестре как `candidate`/`experimental` | не установлены и не прошли smoke-тест | объявить поддержку без проверки |

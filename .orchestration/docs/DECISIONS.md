# Architecture decisions v0.2

English | [Русский](DECISIONS.ru.md)

| # | Decision | Rationale | Alternative and why it was rejected |
|---|---|---|---|
| D1 | Python 3.11 stdlib, TOML configuration | `tomllib` is in the stdlib, existing scripts are Python, zero dependencies | YAML needs PyYAML; JSON has no comments |
| D2 | One CLI `scripts/orch.py` and the `orchlib` package | one entry point for the owner agent; testable modules | the v0.1 shell scripts were hard to test |
| D3 | Codex quota from `codex app-server` (`account/rateLimits/read`) | live data within 1 s without an active Codex session; logs stay as a fallback | session logs only: stale between sessions |
| D4 | Claude quota from the statusline input (`rate_limits`) through a tap | official source, refreshed on every owner reply; the user's own statusline is kept by chaining | the undocumented OAuth usage endpoint was rejected |
| D5 | A stale quota (> 30 min) counts as unknown for routing; the owner sees a conditional hint when the last reading was low and its window has not reset | heavy work does not rely on old data; a low reading before a window reset can only go down | use the last value for automatic selection: may overstate the remaining quota |
| D6 | One one-shot worker per task (`hc run`), no `/clear` and restarts | fresh context by default, cwd set at start | the persistent peer panes of v0.1 |
| D7 | The worker does not commit; the commit happens in `collect` | the Codex sandbox protects `.git` | `danger-full-access` contradicts safe defaults |
| D8 | Completion through `hc wait --children` and the report, no mandatory `hc send` | `hc send` from the sandbox needs approval | a mandatory notification would block the worker |
| D9 | Worktrees inside the repository | folder trust is inherited, no dialog for an unattended worker | `~/.herdr/worktrees` (App convention) needs trust for every worktree |
| D10 | Dashboard as a Herdr App mod, reactive through hub terminal labels | no polling, live core data, the mod holds no business state | polling `exec` on a timer: extra redraws and delay |
| D11 | GSD built-in `plan_check` and `code_review` are off in the lean profile | an independent quota-aware worker does the review | the built-in `/gsd-review` lanes call a CLI once with no quotas: kept for the strict profile |
| D12 | The `cross_ai_command` bridge is implemented but off | GSD runs a delegated plan in the root without a worktree; the owner loses review control before the merge | enable by default |
| D13 | Kimi, OpenCode and ZCode are in the registry as `candidate`/`experimental` | Kimi and ZCode did not pass the smoke test; OpenCode passed the `research` smoke test, worktree execution is not verified | declare support without a check |
| D14 | The reserve is checked against the projection after the task: remaining minus the expected spend of running tasks on the same account minus the spend of the new task. Spend is measured at `collect` (`quota_burn`), the estimate is the median of the last 5 solo tasks, otherwise `reserves.*.<weight>_cost_percent` (0 by default); the estimate is capped at `99 - reserve` | field case 2026-11-02: two parallel heavy tasks were admitted at the same 77%, a third at 36% exhausted the 5 h window | comparing the current remaining quota with the reserve admits a task that eats the reserve itself |
| D15 | The task contract has quota spending rules: a long command is one call with the maximum timeout, no polling with `ps`/`tail` | every tool call resends the whole session context; in the field case polling made 102 of 138 requests and 82% of input tokens | a CLI-side limit: not available |
| D16 | Task admission for all projects is serialized through `admission.lock`; `ledger.json` holds active tasks and spend samples per account, weight and window | two projects must not take the same limit at once; missing terminals and entries older than 24 h are dropped on read | local task lists cannot see another project |
| D17 | The quota cache holds the raw reading per account; the window filter and static budget are applied in the project; after a reset with no new reading the window is unknown | project settings do not change the shared reading, and old percents do not pose as a new quota | cache a ready decision for each agent |
| D18 | The projection and the median of the last five solo tasks are computed per window; initial estimates 15% and 3%; the owner's account adds a 10% reserve | short and long windows burn at different rates, the owner needs capacity to manage | one minimum remaining value and a zero estimate |
| D19 | `collect` stops the worker before the commit; with `--keep-worker` it does not commit; `.planning/` is forbidden in the branch and worktree; merge is checked before the worktree is removed | rules out writes after the check and loss of changes on a conflict | remove the worktree before a trial merge |
| D20 | A repeated id needs `--replace`, which archives the record and the report; `dispatch --of` excludes the author's account for an independent review | evidence of the old task is kept, and the review does not reach the author through another agent variant | reuse the id and compare only agent names |
| D21 | Owner handoff relies on GSD `/gsd-pause-work` and `/gsd-resume-work`; `orch.py owner set` checks the freshness of `.planning/HANDOFF.json` and changes only `owner` | GSD already has a handoff format that any runtime with GSD installed understands | a custom handoff file: duplicates GSD |
| D22 | Owner hints (`orch.py advice`) only advise; a human runs compact, clear and owner switch | these actions change the human's session and cannot be undone for its context | automatic clear: context is lost at a wrong point |
| D23 | Owner context size: Claude from the statusline (`context_window`, fallback: session log), Codex from the session log; no context hint for other runtimes | official sources without asking the model | an estimate by message count: inaccurate |
| D24 | Template update check: a `vX.Y.Z` tag through `git ls-remote --tags`, 24 h cache, no automatic update | works without `gh` and a token; the project knows its version from `.orchestration/template.toml` | GitHub API: rate limits and a token |
| D25 | Advice commands are copied to the clipboard through `exec("powershell", ["Set-Clipboard", ...])` | the Herdr App mod API has no clipboard call; the App runs on Windows in the verified path | text selection in the mod: the App does not support it |
| D26 | The hub exits when the project folder is gone or no live terminal works inside the project for `idle_exit_minutes` | a forgotten hub keeps publishing for a deleted or abandoned project; App panes, the owner and workers are terminals in the project, so a used project keeps its hub | a fixed lifetime: would stop a hub that a person is watching |
